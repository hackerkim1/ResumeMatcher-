# ResumeMatcher：简历 × 岗位匹配分析器

输入一份简历和一个（或一批）岗位描述，输出匹配分数、技能缺口、简历修改建议和可能被问到的面试题。

## 设计思路

- **模型负责理解，代码负责计算**：模型把简历、岗位描述抽取成结构化数据，并逐项判断技能是否满足、给出依据；总分、学历和学校检查都由纯代码完成，结果确定、可测试。
- **岗位技能清单以 JD 为准**：模型漏判、多判、改写技能名，都由代码对齐纠正，评分的分母不受模型波动影响。
- **依据核对**：模型说“满足”时，依据必须能在简历原文里找到相应片段，否则降级为不满足并标记“依据存疑”。
- **岗位库先粗筛后精排**：向量检索挑出候选岗位，再逐个详细评分，最终按总分排序。

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

然后用编辑器打开 `.env`，在 `SILICONFLOW_API_KEY=` 后面填入你的 key。`.env` 已被 `.gitignore` 忽略，不会被提交。

## 使用

### 一份简历对一个岗位

```bash
python -m resume_matcher.cli match --resume data\samples\resume.txt --job data\jobs\llm_app_engineer.txt
```

简历支持 `.txt` 和 `.pdf`，岗位描述为 `.txt`。输出包含：总分与各维度满足率、学历与院校检查、每项技能的判断和依据、简历修改建议、可能被问到的问题。

### 一份简历对岗位库，推荐最合适的岗位

```bash
python -m resume_matcher.cli recommend --resume data\samples\resume.txt --k 5 --brief
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `--resume` | 简历文件 | 必填 |
| `--jobs-dir` | 岗位库目录，里面放若干 `.txt` 岗位文件 | `data\jobs` |
| `--jobs-file` | 改用抓取的岗位库（`jobs.jsonl`），此时不再读 `--jobs-dir`；抓取的岗位用独立的向量集合，不影响样例岗位 | 无 |
| `--track` | 只在这个专业方向里检索（元数据过滤），需要和 `--jobs-file` 一起用 | 不过滤 |
| `--k` | 检索前几个候选岗位并详细评分 | 3 |
| `--brief` | 只显示排名，不显示每个岗位的完整报告 | 关 |

每次运行会先同步岗位库：只给新增的岗位计算 embedding，改过的岗位替换旧版本，被删除的文件从库里移除。

**关于 `--k`**：检索只说明“话题相近”，不说明“够不够格”，它挑不进来的岗位不会被评分。岗位库较大时，`--k` 要取得比想看的名次多得多（例如想看前 3 名，取 10 到 20）。

### 网页版

```bash
.venv\Scripts\streamlit run app.py
```

浏览器会打开页面，有两个标签页，功能和上面两条命令一一对应：

- **单岗位匹配**：上传简历（txt/pdf）和岗位描述（txt），或直接粘贴文字，点“开始分析”。结果包括匹配度和各维度进度条、学历院校检查、每项技能的判断和依据、修改建议、面试题。
- **岗位库推荐**：上传或粘贴简历，用滑块选 k，点“开始推荐”。结果是一张排名表，每个岗位可展开查看完整报告。如果本机已经抓取过岗位（有 `jobs.jsonl`），会多出"岗位来源"选项（样例岗位 / 抓取的岗位），选后者时还可以按"专业方向"过滤。

注意：

- 必须用 `streamlit run` 启动。直接 `python app.py`（包括在 PyCharm 里点运行按钮）只会打印一串 `missing ScriptRunContext` 就退出。想在 PyCharm 里一键运行，可以新建运行配置：类型选 Python，改为“模块名” `streamlit`，参数填 `run app.py`。
- 第一次打开要几秒加载；点击后分析一个岗位约十几秒，推荐是逐个岗位评分，岗位越多越慢。
- 简历只在内存中处理，不写入磁盘。页面上不输入 API key，只从 `.env` 读取。
- txt 文件支持 UTF-8 和 GBK（Windows 记事本默认保存的编码）。PDF 里没有文字层（扫描件）时会提示。

## 评分规则

```
总分 = Σ(权重 × 满足率) ÷ Σ(参与计算的权重) × 100
```

| 维度 | 权重 | 满足率 | 不参与的情况 |
|---|---|---|---|
| 必备技能 | 70 | 判为满足的项数 ÷ 必备技能总项数 | 岗位没有必备技能 |
| 年限 | 15 | min(简历年限 ÷ 要求年限, 1) | 岗位要求年限为 0 |
| 加分项 | 15 | 判为满足的项数 ÷ 加分技能总项数 | 岗位没有加分技能 |

不参与的维度不进计算，剩余权重按比例放大。权重在 `resume_matcher/config.py` 里调整。

**学历与院校单独检查，不计入总分**：学历按 专科 < 本科 < 硕士 < 博士 比较；院校层次查 `data/schools.json` 的名单，名单里查不到时显示“无法判断”，不当作不达标。要求里同时写了多个层次（如 985/211）时，取最低的作为门槛。`data/schools.json` 目前只有示例，请自行补全并以教育部公布的名单为准。

## 更新院校名单

`data/schools.json` 由脚本根据教育部公布的“985 工程”“211 工程”页面生成，文件里记录了来源网址和抓取日期：

```bash
python -m resume_matcher.schools_builder           # 只预览，显示数量、校验警告和与现有文件的差异
python -m resume_matcher.schools_builder --write   # 确认无误后写入
```

脚本会检查 985 是否为 39 所、211 是否为 112 所、985 是否都在 211 名单里；数量对不上会给出警告。页面解析不到校名时不会覆盖现有文件。

名单是教育部 2005、2006 年的版本，之后改过名的学校（如国防科学技术大学、第二军医大学）需要自行留意。校名目前是精确匹配：简历里写校区后缀（如“中国地质大学（武汉）”）或简称（如“北邮”）会被判为未收录。

## 抓取岗位数据（可选，仅供个人学习）

岗位库默认只有 4 个样例。想要覆盖更多专业方向，可以从[国聘](https://www.iguopin.com/)小规模抓取真实岗位：

```bash
python -m resume_matcher.crawler --all                  # 所有专业方向：9 个方向、27 个关键词，约 300 条
python -m resume_matcher.crawler --track 数据           # 只抓一个专业方向的关键词
python -m resume_matcher.crawler --keyword 数据分析     # 只抓一个关键词
```

专业方向和搜索关键词的对照表在 `resume_matcher/tracks.py`，是我们自己定的分类（国聘返回的"专业要求"不统一，不适合直接用来过滤）。

**所有岗位存在同一个文件里**：`data/crawled/iguopin/jobs.jsonl`，一行一个岗位，含完整正文（`text`）和元数据（专业方向、关键词、专业要求、学历、经验、薪资、更新时间、抓取日期）。按岗位编号去重，重复运行不会重复写，也不会覆盖已有的。该目录已被 `.gitignore` 排除，**不要提交或公开这些数据**。

抓下来之后，用岗位库推荐检索，可以按专业方向缩小范围：

```bash
python -m resume_matcher.cli recommend --resume data\samples\resume.txt --jobs-file data\crawled\iguopin\jobs.jsonl --track 数据 --k 8 --brief
```

程序内置的约束（都有测试）：

| 约束 | 做法 |
|---|---|
| 先查 `robots.txt` | 被禁止就一个请求都不发；读不到也不抓 |
| 请求间隔 | 至少 1 秒，默认 3 秒，跨关键词也一样 |
| 总量 | 每个关键词最多 30 条，一次运行总共最多 300 条，超过会报错，不会悄悄截断；**总量平均分给各个关键词**（27 个关键词时每个 11 条），避免前面的方向把名额用光 |
| 请求次数 | 每个关键词最多翻 3 页，一次运行最多 60 次请求；岗位描述直接来自列表接口，不逐个请求详情页，`--all` 实际只需约 27 次 |
| 异常就停 | 遇到登录、验证码、限流（401、403、429）、返回结构异常，立刻停止，不重试、不绕过；已收集的部分会保存 |
| 个人信息 | 只保留岗位文字和专业、学历等要求；联系人和各类内部 ID 一律丢弃 |
| 不伪装 | 不带 Cookie 或令牌，User-Agent 如实说明用途 |

使用前请注意：

- **请先自己阅读国聘的用户协议，确认个人学习用途的小规模抓取可以接受。** 我没有找到它的协议原文，无法替你判断。
- 程序调用的是网站页面自己使用的数据接口，不是对外公开的 API，网站改版后可能失效，失效时会提示"数据结构和预期不同"并停止。
- 国聘主要是央企、国企的岗位，且偏校招；一个平台的一个切片不是"全部岗位"（见下方"已知局限"）。
- "专业要求"有时写的是"详见职位描述"，这种当作"不限"处理。

|---|---|
| `resume_matcher/config.py` | 读取环境变量，集中管理配置、路径和评分权重 |
| `resume_matcher/schemas.py` | 数据结构（Pydantic） |

| `resume_matcher/judge.py` | 逐项技能判断，并与 JD 技能清单对齐 |
| `resume_matcher/grounding.py` | 依据核对 |
| `resume_matcher/scoring.py` | 评分、学历/学校检查（不调用模型） |
| `resume_matcher/pipeline.py` | 完整流程：抽取 → 判断 → 评分 |
| `resume_matcher/library.py` | 岗位库的向量索引与检索 |
| `resume_matcher/recommend.py` | 岗位库推荐 |
| `resume_matcher/report.py` | 把结果排版成文本 |
| `resume_matcher/schools_builder.py` | 从教育部页面生成院校名单 |
| `resume_matcher/crawler.py` | 从国聘小规模抓取公开岗位（仅供个人学习） |
| `resume_matcher/tracks.py` | 专业方向与搜索关键词的对照表 |
| `resume_matcher/jobsfile.py` | 读写 `jobs.jsonl`（一行一个岗位，按岗位编号去重） |
| `resume_matcher/documents.py` | 读取简历和岗位描述（txt/pdf，按路径或按上传的字节） |
| `resume_matcher/services.py` | 组装模型、链、缓存、院校名单和岗位库，命令行和网页共用 |
| `resume_matcher/cli.py` | 命令行入口 |
| `resume_matcher/view.py` | 网页上的结果展示 |
| `app.py` | 网页入口（Streamlit） |
| `data/` | 岗位库、样例简历、院校名单 |
| `tests/` | 测试 |

运行时会生成两个本地目录，都已被忽略，可以随时删除，下次运行自动重建：

- `.cache/jobs/`：岗位抽取结果缓存。同一份岗位描述只抽取一次；岗位描述内容或抽取提示词变了，缓存自动作废。
- `.job_db/`：岗位库的向量索引。

## 已知局限

- **模型判断的准确度只在很小的样本上验过**：1 份简历、4 个岗位，没有系统的标注测试集。对“SQL 算不算 MySQL”“用过 Streamlit 算不算会可视化”这类边界情况，模型倾向于保守，一律判为不满足。
- **依据核对只能拦住对不上原文的依据**：模型引用了真实的原文、但推理不成立时，拦不住。
- **所有技能权重相等**：必备技能里“Python”和“了解 Git”占同样的分，没有区分重要程度，也没有区分“精通”和“了解”。
- **岗位描述里的软素质不参与评分**（如沟通能力），抽取时被排除。
- **“A 或 B”的二选一要求会被拆成两项都必备**，对这类岗位要求偏严。
- **简历抽取、逐项判断每次调用模型，结果可能有波动**；只有岗位抽取有缓存。同一份简历的检索距离在不同运行之间也会略有变化。
- **模型给的依据有时比较笼统**：例如把整行技能清单摘抄下来作为依据，而不是最能说明问题的那一句。依据核对只检查它是否出自原文，不检查它是否贴切。
- **抓取的数据偏校招、偏央企国企**：数据只来自国聘一个平台。第一次抓取的 297 条里，213 条是校招、81 条社招；互联网公司和民企很少；117 条没有写具体专业。它是一个平台的一个切片，不是“全部岗位”。
- **检索和评分会不一致，k 要取得比想看的名次大**：真实运行中，用样例简历在 297 条里检索前 5 个，结果是 1 个数据分析岗加 4 个前端开发岗，更对口的算法工程师没有进入候选（检索用的查询文本里"Streamlit、做前端"出现了两次，把检索拉向了前端）。限定"计算机/软件"方向并取前 8 个后，算法工程师才出现，而且它的检索距离在 8 个里最远、得分却最高。所以检索只负责缩小范围，不能代替评分。
- **分数整体偏低**：样例简历是一份很薄的本科简历，而校招岗位常要求硕士、列出很长的技能清单，所以抓取的岗位上最高也只有十几分到三十几分。这个分数说明的是"技能清单被满足的比例"，不是"值不值得投"。
- **依据核对对“模型改写成自己的话”只做了有限的容错**：只要依据里的英文术语都出现在简历里就算有依据；纯中文的改写仍可能被误判为存疑。
- **院校只有 985/211 两个层次，且校名是精确匹配**：不是 985/211 的学校、写了校区后缀或简称的学校，都显示“无法判断”，分不清“确实不是”和“名单里没有这个名字”。
